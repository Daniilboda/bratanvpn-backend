# Access key hashing — отложенное решение

Статус: **не реализуем сейчас**. Вернёмся перед реальным запуском с пользователями.

Дата фиксации: 2026-07-22

---

## Зачем вообще хэшировать

Хэширование защищает не от администратора, а от **утечки базы данных**.

- Если в БД лежит обычный `access_key` (plaintext) и база утекла — злоумышленник сразу может подключаться.
- Если в БД лежат только хэши — утечка даёт бесполезный набор значений (без возможности восстановить ключ).

То, что ключи создаёт админ вручную, **не отменяет** эту защиту.

Публичные ключи AmneziaWG / WireGuard и `vpn_ip` **хэшировать не нужно** — они нужны серверу в исходном виде для peer/config.

---

## Практический выбор для текущего этапа

### Можно пока хранить ключи открыто, если:

- проект на ранней стадии;
- пользователей мало;
- важно видеть и при необходимости повторно отправлять существующий ключ;
- база доступна только backend-серверу;
- риск утечки понятен и принят.

### Лучше хранить хэши, если:

- ключ фактически равен логину и паролю одновременно;
- один ключ даёт доступ к VPN;
- не обязаны восстанавливать пользователю старый plaintext-ключ;
- при потере ключ отзывается и создаётся новый.

---

## Целевая логика для BratanVPN (когда вернёмся)

1. Пользователю ключ показывается **при создании один раз**.
2. Потерял — старый ключ **отзывается**, создаётся **новый** (не «восстановить из БД»).
3. В админке можно показывать не полный ключ, а маску, например: `BRTN-****-****-91PX`.
4. Перед реальным запуском с пользователями `access_key` лучше хэшировать.

Рекомендуемая схема хранения токена (когда будем делать):

- увеличить энтропию генерируемого ключа;
- в БД: `key_hash = HMAC-SHA256(pepper, key)` (pepper в `.env`, не в Git) — удобный lookup;
- либо Argon2id + blind index, если захотим «парольный» запас прочности;
- plaintext не хранить и не отдавать в `list` после создания.

Подробный разбор вариантов и аудита: `docs/BratanVPN_security.xlsx`.

## Решение сейчас

**Хэширование access key пока не реализуем**, чтобы не усложнять разработку MVP.

Перед продом / реальными пользователями — открыть этот файл и внедрить хранение хэшей по схеме выше.
